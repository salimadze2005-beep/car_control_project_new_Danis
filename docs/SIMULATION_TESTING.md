# Полигон и запись заездов

## Карты

`simulation/tracks/test_ground.csv` — отдельная карта с тремя разнесёнными
зонами: восьмёрка, змейка, повороты. Между зонами нужно перемещаться вручную;
это не единая замкнутая трасса. Для повторяемых испытаний удобнее отдельные
`figure_eight.csv`, `slalom.csv`, `turns.csv`.

Ширина коридора 4 м, шаг конусов около 2 м; все размеры в метрах.
`*.svg` — схемы, `*.json` — осевые линии и описание. На каждой карте ровно
два оранжевых конуса для штатного FSDS start/finish. Карты используют штатные
модели конусов FSDS. Пользовательские SolidWorks-модели пока не импортированы.

На восьмёрке оставлен открытый перекрёсток. Реактивный контроллер только по
конусам может выбрать неверную ветку: прохождение восьмёрки не объявляется
успешным без проверки планирования маршрута. Змейка открытая, длиной 90 м:
останавливайте автомобиль перед концом. Повороты — замкнутый контур с четырьмя
90-градусными поворотами радиусом 8 м. Физика и размеры штатной машины сохранены.

Из Windows PowerShell, при закрытом FSDS:

```powershell
python '\\wsl.localhost\Ubuntu-22.04\home\danis\car_control_project_new_Danis\tools\launch_fsds_test.py' --track test_ground
```

Скрипт использует `C:\FSDS`, создаёт отдельную папку `test_runs`, копирует туда
карту и settings с камерой. Существующие settings не перезаписываются. Для
mirrored-сети передайте `--bind-address 127.0.0.1`; для NAT адрес шлюза определяется
автоматически. FSDS запускается через штатный `-CustomMapPath`.
На этом Radeon запускатель по умолчанию добавляет
`-ini:Engine:[ConsoleVariables]:r.Vulkan.SubmitAfterEveryEndRenderPass=1`.
Настройка применяется до первого кадра и обходит воспроизведённый startup
`VK_ERROR_DEVICE_LOST`. Она может снижать производительность; для сравнительных
тестов предусмотрен `--vulkan-submit-mode default` (здесь снова воспроизводилось падение).
Не заменяйте её на `-norhithread`: в проверке он дал белое изображение камеры.
Простой запуск FSDS.exe без запускателя не получает этот обход автоматически.
Альтернатива: в меню FSDS выбрать CustomMap и абсолютный Windows-путь к CSV.
После смены карты перезапустите ROS2 bridge, чтобы обновились Track и координаты.

WSL:

```bash
cd /home/danis/car_control_project_new_Danis
source /opt/ros/humble/setup.bash
source simulation_ws/install/setup.bash
ros2 launch car_control_sim fsds_drive.launch.py host:=АДРЕС_ИЗ_СКРИПТА
```

Профиль начинает в MANUAL. Проверьте направление движения перед AUTOPILOT.
Повторная генерация: `python3 tools/generate_test_tracks.py`.

## Запись

Исправление ракурса 19.09.2026: камера `front` теперь имеет `X=0.75`, `Y=0`,
`Z=+0.55` м и `Pitch=-5` градусов. В FSDS 2.2.0 система координат камеры —
X вперёд, Y влево, Z вверх (`CarPawnSimApi::createCamerasFromSettings` использует
`CoordFrameTransformer::fromLocalEnu`). Прежний `Z=-0.55` размещал камеру под
машиной/землёй, что подтверждено кадром записи `20260918_232240_351763`.
Это ошибка настройки камеры, а не MP4-кодирования. Для применения перезапустите
FSDS через запускатель; старые `test_runs/*/settings.json` являются снимками
прежних настроек. Обычный Windows `C:\FSDS\settings.json` также исправлен.
Уже записанное видео нельзя превратить в отсутствующий вид сверху.

19.09.2026 новый ракурс проверен визуально в записи `20260919_120835_843931`:
дорога под камерой, впереди конусы, внизу виден нос машины. После обхода Vulkan
получены настоящие кадры, телеметрия и MP4. Это стационарная проверка, не
подтверждение прохождения трассы автопилотом.

Кнопки START/STOP RECORD в существующей панели используют новый recorder.
Либо из sourced WSL-shell:

```bash
python3 tools/fsds_record.py start
python3 tools/fsds_record.py status
python3 tools/fsds_record.py stop
```

После STOP формируется MP4; при длинном заезде это занимает время. Повторное
нажатие STOP не должно прерывать финализацию. Проверяйте `summary.json`: состояние
`complete` означает окончание, `encoding_failed` — исходные кадры сохранены,
но видео не собрано. `video_created=false` и предупреждение показывают отсутствие камеры.

Каждый заезд хранится в отдельной папке `recordings/`:

| Файл | Содержание |
|---|---|
| `camera.mp4` | Видео с реальным темпом поступления кадров; пропуски заполняются предыдущим изображением |
| `frames/*.png` | Все принятые исходные кадры без потерь; позволяют восстановить MP4 |
| `frames.csv` | Индекс, имя кадра, время получения, ROS timestamp, разрешение, encoding |
| `telemetry.csv` | Координаты, yaw, скорости, целевая скорость и ошибка, команды, возраст данных, настройки руля |
| `events.jsonl` | Полные status/command, наблюдаемые конусы и controller config, ROS-ошибки `/rosout`, изменения параметров, сбросы времени |
| `track.json` | Последняя полученная трасса; изменения также остаются в events |
| `summary.json` | Длительность, дистанция, скорость, RMSE скорости при свежем enabled-status, сбои, качество записи |
| `report.md` | Краткий читаемый отчёт по-русски с метриками и предупреждениями |
| `health.json` | Живое состояние записи, наличие кадров и одометрии |
| `metadata.json`, `source_changes.patch`, `configs/` | Версия Git, локальные изменения, копии исходных конфигураций |
| `recorder.log` | Вывод процесса записи |

Исходные конфиги — контекст эксперимента, а не доказательство реально применённых
параметров. Реальные controller-параметры публикуются в `events.jsonl` вместе
с каждым status. `/parameter_events` сохраняет изменения после старта recorder.

`elapsed_s` — монотонное время получения на компьютере recorder. `ros_stamp_s` —
время источника; это разные шкалы. Нулевой кадр MP4 соответствует
`summary.video_start_elapsed_s`; кадр MP4 с индексом N соответствует времени
`video_start_elapsed_s + N/video_fps`. Синхронизация по receipt не компенсирует
сетевую задержку: для анализа задержек сравнивайте source timestamps отдельно.
CSV использует последние команды/status, а не интерполяцию: смотрите age-колонки.

Частота MP4 не повышает реальную частоту камеры. Старое поведение писало 96 кадров
за 36,7 с как 15 FPS, получая 6,4 с видео. Теперь паузы сохраняются. PNG занимают
дополнительное место. При ошибке записи на диск recorder завершается с ошибкой.

Восстановление после прерванной финализации, когда `camera.mp4` отсутствует:

```bash
python3 tools/recover_video.py recordings/ИМЯ_ЗАЕЗДА
```

## Ограничение пользовательских CAD-моделей

Переданы SolidWorks `.SLDPRT` и `.SLDASM`, а установленный FSDS — готовая
упакованная Unreal 4.27.2 игра. CSV может менять расстановку конусов, но не
импортирует новые меши. Требуются экспорт геометрии совместимым CAD-инструментом,
полный FSDS Unreal-проект и Editor 4.27 для импорта/cook. Сборка автомобиля также
требует правильных колёс, иерархии, материалов и проверки масштаба; замена физики
маленькой машиной не производится без размеров и массы.

Семь исходных CAD-файлов хранятся локально в `simulation/cad_sources/` и не
публикуются в GitHub. `manifest.json` содержит SHA-256 и статус
`integrated_into_fsds=false`.

## Проверка на этом компьютере, 19 сентября 2026

На DIGMA Pro Sprint N с Radeon Vega после обновления драйвера до
`31.0.21925.1001` сбой Vulkan воспроизводился даже с настройками ранее успешного
запуска. Изменение высоты камеры не является достаточным объяснением сбоя.
Применённый в запускателе startup-параметр SubmitAfterEveryEndRenderPass позволил
загрузить `/Game/customMap`, получить 470 конусов, телеметрию и изображение камеры;
повторный запуск штатным Python-скриптом также прошёл загрузку и подключение ROS.
Длительная устойчивость и движение автопилотом отдельно не проверялись.
Вариант `--renderer d3d11` не работает: в пакете отсутствует Global shader library.
Реестр Windows и параметры таймаутов видеодрайвера не менялись.

Дополнительный `simulation/upstream/fsds-2.2.0-camera.patch` исправляет
жёсткие 5 секунд RPC timeout и перехватывает `std::exception` при запросе
изображений. Ошибки идут в ROS logger и попадают в events.jsonl. Применение
идемпотентно через `tools/prepare_fsds.py`, сборка — `tools/build_ros2.sh --fsds`.
